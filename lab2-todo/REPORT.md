# Отчёт по лабораторной работе 2

## Тема и цель

Я разработал ToDo-приложение на HTML, CSS и чистом JavaScript. Цель работы — создать задачи, редактировать и удалять их, отмечать выполнение, искать и фильтровать список, сортировать задачи по дате, вручную менять их порядок и сохранять данные между загрузками страницы.

## Ход работы

Я начал с базовой страницы, которая создаёт интерфейс через DOM API и позволяет добавлять задачи. Следующим этапом добавил редактирование, завершение и удаление задач, а также хранение состояния в `localStorage`. В финальной доработке реализовал поиск, фильтр по статусу, выбор направления сортировки по дате и перетаскивание для ручного порядка. Состояние хранится массивом задач; при ручной перестановке приложение меняет порядок элементов массива и сохраняет его.

История Git сохраняет этапы разработки обеих лабораторных в одной feature-ветке. В частности, начальная реализация ToDo и этап сохранения задач выделены отдельными коммитами. В корне репозитория есть обзор обеих работ и инструкция локального запуска.

## Устройство приложения

В HTML находится базовая оболочка документа и ссылки на CSS и JavaScript. Скрипт создаёт семантические элементы формы, секции, заголовки, фильтры и список задач через `document.createElement`, задаёт текст через `textContent` и соединяет элементы методами DOM. Сборка содержимого не использует `innerHTML`.

Каждая задача содержит идентификатор, название, дату и признак выполнения. Для поиска используется название, для фильтра — статус, а сортировка сравнивает даты в ISO-формате. В режиме «Вручную» перетаскивание доступно для полного списка без активного поиска; после перестановки порядок массива записывается в `localStorage`. В режиме сортировки по дате ручная перестановка выключена, чтобы дата и пользовательский порядок не конфликтовали. Ключ хранения — `webprog-labs-todo-tasks`.

## Проверки

При подготовке выпуска я проверил синтаксис JavaScript командой `node --check` и просмотрел, что HTML не содержит разметки интерфейса. Эти проверки не заменяют визуальный прогон приложения в браузере.

Перед отправкой я проверю в браузере следующие сценарии и отмечу фактический результат:

1. Добавить две задачи с разными датами; попробовать отправить пустое название и дату.
2. Изменить название и дату, отменить редактирование, удалить задачу.
3. Отметить задачу выполненной и проверить зачёркивание.
4. Найти задачу по части названия; очистить поиск; проверить фильтры всех, невыполненных и выполненных задач, включая пустой результат.
5. Выбрать сортировку по возрастанию и убыванию даты.
6. Выбрать «Вручную», перетащить строку выше/ниже, перезагрузить страницу и убедиться, что порядок восстановился.
7. Включить поиск или фильтр и убедиться, что ручное перетаскивание недоступно; очистить условия и повторить перестановку.
8. Проверить раскладку на ширине телефона и настольного экрана; drag-and-drop проверять мышью в настольном браузере.

Визуальный браузерный прогон должен выполнить автор перед сдачей. До этого я не отмечаю пункты выше как пройденные.

## Подготовка к защите

Я объясню, что интерфейс создаётся DOM-методами, задачи представлены объектами, а отображаемый список вычисляется с учётом поиска, фильтра и сортировки. Затем покажу разницу между ручным порядком и сортировкой по дате и объясню, почему ручной порядок сохраняется в массиве `localStorage`.

### Вопросы и краткие ответы

**Почему содержимое интерфейса отсутствует в HTML?**

Требование лабораторной просит строить элементы страницы через JavaScript и DOM API. HTML задаёт документ и подключения ресурсов.

**Как приложение ищет задачи?**

Оно приводит введённый запрос и названия к нижнему регистру и проверяет, содержит ли название запрос.

**Как устроен фильтр статуса?**

При выборе фильтра в отображаемый массив попадают все задачи, только невыполненные или только выполненные.

**Как сохраняется ручной порядок?**

При перетаскивании меняется порядок задач в массиве, после чего весь массив сериализуется в `localStorage`. При запуске массив восстанавливается без пересортировки.

**Почему нельзя перетаскивать задачи, когда включена сортировка по дате или фильтр?**

Сортировка по дате задаёт отображаемый порядок сама, а фильтр или поиск скрывает часть задач. Перестановка разрешена только для полного списка в ручном режиме, чтобы не менять порядок скрытых элементов неожиданно.

**Что произойдёт, если данные в хранилище повреждены?**

Ошибку разбора приложение перехватывает и показывает пустой список. При восстановлении также отбрасываются записи с некорректными полями и датами.
